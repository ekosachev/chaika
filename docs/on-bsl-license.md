# Лицензия проекта: Business Source License (BSL 1.1)

Предлагаю использовать для проекта **Business Source License 1.1 (BSL)**.

## Зачем нам BSL

Мы хотим, чтобы исходный код проекта был публичным:

* чтобы рекрутеры могли посмотреть исходники;
* чтобы разработчики могли изучать архитектуру и код;
* чтобы можно было делать fork и экспериментировать;
* чтобы проект оставался открытым для обучения и разработки.

При этом мы **не хотим, чтобы любой человек мог просто взять проект, развернуть его и использовать для своей коммерческой деятельности**, например репетитор мог бесплатно использовать платформу для работы со своими платными учениками.

BSL позволяет сделать именно это: **код публичный и доступный для изучения, но production/commercial use ограничен условиями лицензии.**

Важно: такой проект формально не является Open Source в смысле OSI, пока действует BSL.

---

## Что разрешено обычному пользователю

Пользователь может:

* смотреть исходный код;
* клонировать репозиторий;
* делать fork;
* изменять код;
* использовать проект для разработки;
* использовать его для тестирования и оценки;
* создавать свои модификации;
* распространять модифицированные версии в рамках условий BSL.

То есть человек может спокойно скачать проект и разобраться, как он работает.

---

## Что запрещено

При выбранных нами условиях BSL пользователь **не сможет использовать проект в production для своей коммерческой деятельности**, если такое использование не разрешено `Additional Use Grant`.

Например:

> Репетитор скачал проект → развернул на своём сервере → ведёт через него работу с платными учениками.

Такое использование будет запрещено без отдельной коммерческой лицензии.

---

## Что происходит с fork

Fork не позволяет обойти лицензию.

Если человек берёт наш код и делает на его основе модифицированный проект, BSL продолжает распространяться на оригинальный код и производные работы.

Нельзя сделать:

```text
наш проект (BSL)
        ↓
fork
        ↓
изменили код
        ↓
поставили MIT
        ↓
продаём
```

Простое изменение файла `LICENSE` не даёт человеку права перелицензировать наш код.

При этом человек может написать полностью независимую реализацию с нуля. BSL не запрещает создавать конкурирующие проекты, основанные только на идеях.

---

## Можно ли дать отдельному человеку коммерческие права

Да.

Мы можем оставить публичную BSL для всех, но отдельно выдать конкретному человеку или компании **коммерческую лицензию**.

Например:

```text
Обычный пользователь:
production use ❌

Компания X:
production use ✅
```

При этом публичная лицензия проекта не меняется.

Для такой схемы важно заранее определить, кто из команды имеет право выдавать коммерческие лицензии на проект.

---

## Что такое Additional Use Grant

BSL позволяет дополнительно указать, какие варианты production use мы разрешаем.

Для нашего проекта предполагается максимально простой вариант:

> Использование проекта для разработки, тестирования, оценки и обучения разрешено. Production use для коммерческой деятельности требует отдельной лицензии.

Конкретную формулировку нужно определить при подготовке `LICENSE`.

---

## Что происходит с лицензией через несколько лет

У BSL есть **Change Date**.

До этой даты действует BSL.

После неё конкретная версия проекта автоматически переходит на указанную нами **Change License**, например Apache 2.0.

Пример:

```text
2026–2030
BSL
commercial production use ограничен
        ↓
2030
Apache 2.0
commercial use разрешён
```

Поэтому BSL не является вечным запретом на коммерческое использование.

Максимальный срок BSL для версии ограничен четырьмя годами с момента первого публичного релиза этой версии.

Новые версии могут иметь собственные Change Date.

---

## Что должны делать мы как разработчики

Нам нужно:

1. Положить полный текст BSL 1.1 в `LICENSE`.
2. Указать:

   * правообладателей;
   * название Licensed Work;
   * `Additional Use Grant`;
   * `Change Date`;
   * `Change License`.
3. Не менять сам текст BSL, кроме предусмотренных в ней параметров.
4. Убедиться, что у команды есть необходимые права на весь наш код.
5. Не включать в лицензию нашими правами чужой код и зависимости.

Отдельной регистрации проекта или лицензии где-либо не требуется.

---

## Что с зависимостями

Наш собственный код может находиться под BSL.

Сторонние библиотеки и зависимости **не становятся BSL автоматически**. Они продолжают использовать свои собственные лицензии.

Например:

```text
наш код             → BSL
PostgreSQL          → своя лицензия
React                → своя лицензия
Rust crates          → свои лицензии
и т.д.
```

Это нормально.

---

## Что с внешними контрибьюторами

Мы **не принимаем код от внешних разработчиков**.

Проект разрабатывается только нашей командой.

Это позволяет не вводить CLA и не разбираться с дополнительными copyright-претензиями от случайных contributors.

Если позже мы захотим принимать внешний код, вопрос с правами на contributions нужно будет решить отдельно.

---

## Как будет выглядеть репозиторий

Минимально:

```text
project/
├── LICENSE
├── README.md
├── backend/
├── frontend/
├── ...
```

В `README` желательно явно написать, что проект распространяется под BSL и что production/commercial use ограничен условиями лицензии.

---

## Важный итог

BSL даёт нам следующую модель:

| Возможность                          | Обычный пользователь                           |
| ------------------------------------ | ---------------------------------------------- |
| Читать код                           | ✅                                              |
| Clone                                | ✅                                              |
| Fork                                 | ✅                                              |
| Изменять код                         | ✅                                              |
| Использовать для разработки          | ✅                                              |
| Тестировать                          | ✅                                              |
| Изучать для собеседования/обучения   | ✅                                              |
| Использовать в коммерческой работе   | ❌                                              |
| Получить коммерческие права отдельно | ✅                                              |
| После Change Date                    | ✅ коммерческое использование по новой лицензии |

### Почему это подходит нашему проекту

Мы получаем **публичный исходный код для портфолио и развития проекта**, но защищаемся от сценария, когда кто-то просто клонирует репозиторий и начинает бесплатно использовать его как рабочую платформу для своего бизнеса.

При этом мы сохраняем возможность **отдельно разрешить коммерческое использование конкретным людям или компаниям**.

Главный компромисс: через несколько лет каждая версия проекта автоматически переходит на выбранную нами Open Source-лицензию, например Apache 2.0.
